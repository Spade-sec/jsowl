# 报告输出

每个目标在输出目录下生成独立的报告子目录。扫描完成后用浏览器打开 `report.html` 即可查看交互式总览，无需任何外部资源。

## 目录结构

```text
jsowl-report/
└── example.com/
    ├── report.html          # 交互式主报告：总览仪表盘 + 工作台 + 打印视图
    ├── API报告.html          # API 路径（相对/绝对分组，分页 + 上下文）
    ├── URL报告.html          # 完整 http(s) URL（分页）
    ├── 敏感信息报告.html
    ├── 参数报告.html
    ├── 路由报告.html
    ├── 资源报告.html
    ├── 主机资产报告.html      # 域名 / IP / 内部主机候选（含来源证据）
    ├── api绝对路径.txt       # /a/b/c 形式的纯路径
    ├── api相对路径.txt       # a/b/c 形式的纯路径
    ├── url.txt              # 完整 http(s) URL
    ├── 路由.txt / 参数.txt / 敏感信息.txt
    ├── domain.txt           # 域名清单（标准化、去重，每行一条）
    ├── ip.txt               # IPv4/IPv6 清单
    ├── internal_hosts.txt   # 内部主机候选清单
    ├── report.json
    └── js/
        ├── app.<hash>.js
        └── chunks/
            └── users.<hash>.js
```

同一主机的非根路径或带 query 的多个扫描目标会在主机名后添加稳定 URL 哈希（例如
`example.com-0b2cf73d/`），避免报告相互覆盖。**一个目标的全部产物都在这一个目录里**：
`report.json`、`report.html`、各分项报告、文本清单，以及下载保存的脚本与 chunk（`js/`）。
报告里记录的本地路径（`report.json` 的 `local_path`、资源报告里的“本地路径”列）是**相对该目录**的，
因此始终指向报告旁边的文件。重复扫描同一目标会覆盖该目录中同名文件。

## 报告格式

- **JSON**（`report.json`）：完整序列化 `Result` 结构，适合程序化处理与导入其他工具；
  `hosts`（内容发现的主机）与 `scan_hosts`（扫描关联的主机）是两个独立数组。
- **主机清单**：`domain.txt`、`ip.txt`、`internal_hosts.txt`，内容为标准化、去重后的值，
  每行一条，可直接与其他工具串接。提取来源、分类规则与限制见
  [主机资产提取](host-extraction.md)。
- **HTML**：无需外部资源的交互式报告，`report.html` 是合并总览入口，各分项报告可独立打开。
- **纯文本**：`api绝对路径.txt`、`url.txt` 等纯路径清单，可直接喂给 Burp Suite、fuzz 工具或爬虫。

三者都会保留完整敏感值，不做脱敏。报告会包含完整敏感数据，请严格限制报告目录的访问权限。

## 主报告结构

`report.html` 同时承担三种用途：交付用的总览、日常核查用的工作台、打印/存档用的交付文档。顶部固定导航包含七个页面：

| 页面 | 内容 |
| --- | --- |
| 报告总览 | 攻击面指标、安全发现指标、四张分布图、重点发现、结论口径与自动化边界 |
| 敏感发现 | 发现列表（聚合视图 / 原始命中视图切换）、筛选、排序、分页、详情抽屉、CSV 导出 |
| API 端点 | 后端 API 端点表（方法、路径、域名、证据、参数数、来源、授权、探测状态）、筛选、CSV 导出、详情抽屉（请求规格、请求包、AI 分析） |
| 主机资产 | 域名 / IPv4 / IPv6 / 内部主机候选的筛选与搜索、按可注册域归组、来源证据与源码位置、复制与 CSV 导出；同主题的服务端渲染页面见 `主机资产报告.html` |
| 路由与参数 | 前端框架路由表（含探测结果）与参数名清单；参数统计明细在参数报告 |
| 资源 | 资源类型与响应状态分布、只含可证实信息的说明、资源明细表 |
| 扫描诊断 | 诊断分类与阶段分布、诊断明细表、影响完整性的说明 |
| 报告附件 | 分项报告与纯文本清单入口 |

左侧保留可展开收起的来源文件树，点击节点即按来源路径筛选发现列表。页面顶部展示目标、扫描模式、扫描开始/结束时间与报告生成时间；结果中没有记录扫描时间时只显示“报告生成时间”，不会推算或伪造耗时。

## 统计口径

汇总逻辑集中在 Go 侧一次性计算，随报告以 JSON 内嵌，图表、表格、CSV 与打印视图读取同一份数字，分项报告复用同一套辅助函数，因此各处计数不会互相矛盾。

- **原始命中**：规则在源码中每一次匹配都单独计数（`原始命中数`）。
- **聚合发现**：按 `规则 + 分类 + 等级 + 完整值` 合并后的条数。不同敏感值、不同规则、不同等级永不合并；每条原始证据（来源 URL、行列、源码上下文、该条命中的 AI 评估）都保留在聚合结果内。
- **聚合编号**：按 等级由高到低 → 命中次数由多到少 → 规则名 → 完整值 排序后编号 `G001`、`G002`……同一份结果重复生成编号不变；原始命中视图中的 `R0001` 同理。
- **唯一端点**：按解析后的完整 URL 去重；卡片副标题给出未去重的记录行数。
- **域名**：端点、路由、资源与发现来源主机名的并集。无法解析出主机的相对路径单独归入“（未解析主机）”，不计入域名数，也不并入目标域名。
- **HTTP 方法**：只统计源码中记录的方法；未记录的一律计入“未知”，不默认补为 GET。
- **参数**：URL query、请求体、响应字段与 AST 提取结果去重后的参数名数量，与 `参数.txt` 使用同一实现。
- **资源与解析**：只展示资源类型计数、HTTP 状态码计数与诊断分类计数。结果中没有逐文件解析结论，缺少可靠分母，因此不计算“解析成功率”。
- **优先级**：`P1 = high/critical`、`P2 = medium`、`P3 = low/info`，仅表示建议的查看顺序，不使用综合评分，也不代表漏洞结论。
- **路由与端点分类**：`type=route` 只来自两类来源——命中 `url.vue-route` / `url.react-route*` 规则的静态路由，以及浏览器阶段由注入脚本与 CDP 实际观测到的路由；其余被规则匹配到的引号内 URL 归为 `type=link`（默认兜底分类），不进入路由清单与路由报告。运行时观测会升级同一 URL 上的静态分类（`link` → `route`/`api`），所以 SPA 通过 `history.pushState`/`replaceState`/`hashchange` 切换的路由也会出现在路由清单里。
- **主机资产**：分两类统计，口径不混合。**内容发现**是出现在 JavaScript、内联脚本、文档与 source map
  还原源码中的主机值；**扫描关联**是本次扫描实际访问或被引用对象所属主机（目标、资源、端点、发现来源）。
  两者用同一套归一化与公共后缀分类规则，交叉出现的主机分别计入两类并给出重合数量。
  域名只在公共后缀列表识别出后缀时成立：IP、内部主机候选（含 `.test`/`.local` 等特殊用途后缀与
  配置的内部后缀）各有独立计数，无主机的相对路径不计入；地址属性只说明地址是什么（私网/回环/
  链路本地/组播/未指定），不构成“公网可路由”的判断。发现主机不代表可访问资产——提取过程不做 DNS
  查询、不做连通性探测。

图表（严重性环形图、发现类型、域名排行、HTTP 方法）均可点击或键盘回车下钻到对应列表并应用筛选；图例同时给出可读数量，零数据时显示明确的空状态。

## 筛选与导出

发现列表支持关键词、等级、分类、规则、域名、来源节点筛选，以及表头点击排序和分页；API 端点列表支持域名、方法、关键词筛选。由图表触发的筛选会同步到下拉框，并在列表上方以标签形式展示，可逐个清除或一键清除全部。

CSV 导出覆盖发现（聚合或原始命中视图）、API 端点与主机资产：

- 导出范围是**当前筛选条件下的全部结果**，不是当前页；按钮文案与导出后的提示都会写明条数。
- 文件名为 `jsowl-<范围>-<主机>-<条数>.csv`，只使用安全字符。
- 内容使用 UTF-8 BOM 与 CRLF，中文表头在常见表格软件中可直接正常显示；含逗号、引号或换行的字段按 RFC 4180 加引号转义。
- 以 `=`、`+`、`-`、`@`、制表符或回车开头的字段会加上 `'` 前缀，防止表格软件把扫描得到的值当作公式执行。该防护只作用于导出的 CSV 文本，报告数据本身不被修改。
- 主机资产的导出包含标准化主机、类型、可注册域、公共后缀、后缀状态、地址属性、出现次数、
  数据来源（内容发现 / 扫描关联）、来源证据数与首个来源位置。
- 导出完全在浏览器本地完成，不上传、不经过任何外部服务。

## 打印交付视图

点击顶部“打印 / 保存 PDF”调用浏览器自带打印能力，不新增服务端依赖。打印内容与当前标签页、筛选条件、分页无关，始终按固定顺序输出完整报告：

1. 报告封面（目标、扫描模式、扫描时间、报告生成时间、密级提示）；
2. 报告摘要；
3. 扫描目标、范围与方法说明（含自动化边界声明）；
4. 发现与攻击面统计（等级分布、攻击面指标、主机分布、主机资产两类计数）；
5. 重点发现及证据（完整值、AI 辅助评估、核查建议、全部来源位置与首处上下文）；
6. 优先核查清单；
7. 附录与诊断摘要（聚合发现清单、资源与诊断、参数名、主机清单说明、附件清单）。

打印样式按 A4 排版：隐藏导航、筛选器、分页器与操作按钮，表头跨页重复，长 URL 与代码自动换行，卡片与证据块避免被分页截断。打印范围可切换：

- **完整打印**（默认）：输出全部聚合发现；
- **精简打印**：仅输出前 200 条聚合发现，并在报告内显著标注实际范围与总条数，同时保留切回完整打印的选项。

数据量很大时不会静默截断。项目名称、测试人员与报告编号只在扫描结果确实提供时才展示，否则使用默认标题，不填入虚构信息。

## 自动发现与人工确认的区别

报告严格区分三种层次，并在总览的“结论口径与自动化边界”中说明：

- **规则命中等级**：来自规则定义（critical/high/medium/low/info），是报告中唯一的“等级”。
- **AI 辅助评估**：仅在启用 `-ai` 时存在，是模型给出的参考意见，单独标注为 AI，不作为结论，也不会因聚合而丢失。
- **人工确认结果**：本次报告不含人工确认数据，所有发现的核查状态统一显示为「待人工验证」。

报告不给出 CVSS 分数、风险等级结论或可利用性判定，也不暗示已完成完整人工渗透测试：它呈现的是自动采集与规则匹配的结果，攻击面可能存在未采集到的资源与端点，所有命中都需要人工确认是否真实、是否可利用。

## 本地样例报告

需要人工验证页面效果时，可生成三份内置样例（含多等级、多域名、重复发现、长 URL、源码上下文与诊断信息，以及空结果与大数据量两种边界情形）：

```bash
JSOWL_SAMPLE_REPORT=1 go test ./internal/report -run TestGenerateSampleReport -v
# 输出到 jsowl-report/{sample-report,empty-report,large-report}/
```

该目录已被 `.gitignore` 忽略，不会污染仓库。

## 脚本保存（`output.download_js`）

默认为 `true`。开启后只保存普通 JS 和 chunk，保存位置是**该目标的报告目录**下的 `js/`
（chunk 再进一层 `js/chunks/`），文件名会清理 Windows 非法字符并使用稳定哈希避免 query/重名覆盖。
超过正文上限（`limits.max_body_size`）的脚本不会保存，并在结果中记录 Issue。

`output.js_directory` 只改变这一层目录的名字，且取路径的末段：配置 `assets/js` 得到的是 `js`。
报告目录本身由目标决定（输出根 + 主机名，必要时带哈希），与 `js_directory` 无关；
扫描器与所有报告写入方（CLI、MCP 服务、tools 服务）都用同一个推导函数
（`TargetReportDirectory`），因此报告与其脚本永远落在同一个文件夹里。

开启后流水线会先把所有脚本和 chunk 下载完成，再统一对下载内容做正则匹配和 AST 解析（发现后续脚本/chunk 的递归抓取逻辑不变）。API 响应正文永不保存。
